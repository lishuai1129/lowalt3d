# 通用流程文档：无人机影像 → 材质感知 3DGS → 电磁路损（换场景复用）

> 把整条已跑通的管线参数化。**换一个新场景，只改一个变量 `SCENE`，从头到尾复制命令即可。**
> 环境：`conda activate E:\condaenvs\emmap`（torch 2.8 cu128 / RTX 5070 Ti）
> 基目录：`E:\lowalt3d`

---

## 0. 约定与前置

**设场景名**（每个新窗口都先设一次；改成你的场景名）：

```cmd
set SCENE=scene02
```

**放影像**：把新场景的无人机原图放到

```
E:\lowalt3d\data\%SCENE%\input\*.JPG
```

> ⚠️ 确保 `E:\lowalt3d\data\` 下**只有当前这个场景**（convert.py 会把 data 下每个子目录当一个场景处理）。上一个场景请先归档（见 §7）。

**两种命令行 cwd**（下面每步标了在哪跑）：

- **[PGSR]** 步骤在 `E:\lowalt3d\repos\pgsr`（它的 import 依赖该目录）
- **[根]** 步骤在 `E:\lowalt3d`

## 1. COLMAP 位姿估计 · [PGSR]

```cmd
cd /d E:\lowalt3d\repos\pgsr
python scripts\preprocess\convert.py --data_path E:\lowalt3d\data
```

**产物**：`data\%SCENE%\images\`（去畸变图）+ `data\%SCENE%\sparse\0\`
**注**：若 COLMAP 报某选项 `unrecognised option`，去掉该选项（convert.py 已去过 use_gpu）。

## 2. PGSR 训练 + 网格提取 · [PGSR]

```cmd
python train.py -s E:\lowalt3d\data\%SCENE% -m E:\lowalt3d\outputs\%SCENE%_pgsr -r 4 --iterations 15000 --max_abs_split_points 0 --opacity_cull_threshold 0.05
python render.py -m E:\lowalt3d\outputs\%SCENE%_pgsr --max_depth 10.0 --voxel_size 0.01 --use_depth_filter
```

**产物**：`outputs\%SCENE%_pgsr\{point_cloud\iteration_15000\point_cloud.ply, mesh\tsdf_fusion_post.ply, cameras.json}`
**注**：网格空/破 → 调 `--max_depth`（单位是 COLMAP 归一化，非米；先看训练日志的 `cameras_extent`，`max_depth` 取其 1.5~3 倍）。想更精细几何：`-r 2 --iterations 30000`（更慢）。

## 2b. 地理配准（真实带 GPS 无人机图；恢复米制 + 摆正朝向）· [根]

```cmd
python scripts\georeference.py --images data\%SCENE%\input --cameras outputs\%SCENE%_pgsr\cameras.json --out outputs\%SCENE%_pgsr\geo_transform.json
```

**产物**：`geo_transform.json`（`scale` 米/单位 + ENU 旋转 R + 平移 t）。用无人机 GPS EXIF ↔ COLMAP 相机位置做 Umeyama——**一次解决米制尺度 + 朝向（ENU 的 +Z 向上）**。
**用途**：§5 路损真实 dB、§5b InSite 米制模型。
**无 GPS 时**：量一个已知距离（如某条路宽），手动 `scale = 真实米 / 模型里对应单位数`，后续步骤直接用 `--scale`。残差大 → 用 RTK/PPK 或 GCP。

## 3. 自动材质标注（零下载）· [根]

```cmd
cd /d E:\lowalt3d
python scripts\autolabel_color.py --images data\%SCENE%\images --out data\%SCENE%\material\masks_auto --color
```

**产物**：`data\%SCENE%\material\masks_auto\*.png`（+ `_color` 上色预览）
**复核**：打开 `masks_auto_color\` 看几张。分错就调 `scripts\autolabel_color.py` 的颜色阈值；或改用预训练模型 `scripts\autolabel.py`（需 `pip install transformers` + `set HF_ENDPOINT=https://hf-mirror.com`）。
**类别**：`configs\classes.txt`（7 类）；建筑多的场景可增补类别并同步 `configs\radio_params.yaml`。

## 4A. 可微材质 3DGS（开题创新②，主线）· [根]

```cmd
:: 训练每高斯材质向量(可微，冻结几何)
python scripts\train_gaussian_material.py -s data\%SCENE% -m outputs\%SCENE%_pgsr -r 4 --load_iteration 15000 --masks_dir data\%SCENE%\material\masks_auto --classes configs\classes.txt --mat_out outputs\%SCENE%_pgsr\gaussian_material --epochs 30

:: (可选)加多视角一致性 L_cons 续训
python scripts\train_gaussian_material.py -s data\%SCENE% -m outputs\%SCENE%_pgsr -r 4 --load_iteration 15000 --masks_dir data\%SCENE%\material\masks_auto --classes configs\classes.txt --mat_out outputs\%SCENE%_pgsr\gaussian_material_cons --epochs 8 --lambda_cons 0.5 --init_material outputs\%SCENE%_pgsr\gaussian_material\gaussian_material.pt

:: 高斯材质 → 网格面片(kNN 加权投票)
python scripts\gaussian_to_mesh_material.py --mesh outputs\%SCENE%_pgsr\mesh\tsdf_fusion_post.ply --gaussian_ply outputs\%SCENE%_pgsr\point_cloud\iteration_15000\point_cloud.ply --material_pt outputs\%SCENE%_pgsr\gaussian_material_cons\gaussian_material.pt --classes configs\classes.txt --out_dir outputs\%SCENE%_pgsr\material_gauss_cons
```

**产物**：`gaussian_material[_cons]\gaussian_material.pt`（每高斯材质向量）+ `material_gauss_cons\{face_materials.csv, material_mesh.ply}`

## 4B. 直接投票版（基线/消融对比）· [根]

```cmd
python scripts\assign_material.py --mesh outputs\%SCENE%_pgsr\mesh\tsdf_fusion_post.ply --cameras outputs\%SCENE%_pgsr\cameras.json --images data\%SCENE%\images --out_dir outputs\%SCENE%_pgsr\material_seg --masks_dir data\%SCENE%\material\masks_auto
```

> 消融三方对比：`material_seg`(2D投票) vs `material_gauss`(可微) vs `material_gauss_cons`(可微+一致性)。

## 5. 电磁参数映射 + 射线路损 · [根]

```cmd
python scripts\simple_pathloss.py --mesh outputs\%SCENE%_pgsr\mesh\tsdf_fusion_post.ply --materials outputs\%SCENE%_pgsr\material_gauss_cons\face_materials.csv --cameras outputs\%SCENE%_pgsr\cameras.json --out_dir outputs\%SCENE%_pgsr\pathloss_gauss_cons --grid 60
```

**产物**：`pathloss_*\{pathloss_heatmap.png, los_map.png, pathloss_grid.npz}`
**注**：**必须加 `--cameras`**（用无人机位置判天空侧，TX 才在模型上方）。米制路损需地理配准后加 `--scale <geo_transform 里的 scale>`。

## 5b. 导出 Wireless InSite 模型（`.city` — 材质不丢）· [根]

```cmd
python scripts\export_dae.py --mesh outputs\%SCENE%_pgsr\mesh\tsdf_fusion_post.ply --materials outputs\%SCENE%_pgsr\material_gauss_cons\face_materials.csv --out_dir outputs\%SCENE%_pgsr\insite --geo_transform outputs\%SCENE%_pgsr\geo_transform.json --ground_z0 --target_faces 500000
```

**产物**：`insite\{scene.city, scene.dae, materials_insite.csv}`。

> ⚠️ **在 InSite 里必须加载 `scene.city`，不要加载 `.dae`。**
> InSite 的 COLLADA(.dae) 导入器**不认我们的多材质分组，会把所有面片合并成第一个材质(Concrete)** → 材质全丢（只剩 Concrete + 默认 Brick）。脚本已内置 `write_city`，直接写 InSite **原生 .city**，每个面片带正确材质【索引】，从根上绕过这个坑。

**参数说明**：

- `--geo_transform`：转**米制 + ENU（+Z 向上）**，同时**摆正朝向**（不加则模型是 COLMAP 原始坐标，进 InSite 会**躺平/翻转**）。
- `--ground_z0`：把地面移到 **z≈0**。ENU 原点在无人机飞行高度，不加此项地面会落在 **z≈-80**，放收发机极不便（相对几何不变，不影响路损）。
- `--target_faces`：控面数。InSite 嫌慢就减到 `200000`（见下方提速）。
- `--clean_floaters 0.005`：（可选）删小连通碎块去噪。**注意**：若网格是一整块连通体（毛刺与主体相连），此招删不掉任何面，只能靠减面"抹平"。

### 在 InSite 中加载 + 验证材质对应

1. **File → Open** 选 `scene.city`（原生格式，材质随之进来；换模型时先删掉旧的 City 要素）。
2. **三项验证**（确认材质真的对上了）：

| 检查 | 正确的样子 |
| --- | --- |
| 材质列表 | 有 **4~7 项**（Concrete/Asphalt/Glass/Wood…），而非只有 Concrete + Brick |
| Color by material（按材质着色） | 道路暗、楼灰、植被绿，**分块分明**，非单一颜色 |
| 点选面片看属性 | 已知道路面 = **Asphalt**(σ=5e-4,εr=5.72)，楼面 = **Concrete**(σ=0.015,εr=7.0) |

3. **放收发机**：地面在 z≈0 后，按真实高度放——低空基站 TX≈30m，无人机 RX≈50~100m（正合低空通信主题）。

### InSite 仿真提速（重要）

| 手段 | 操作 | 效果 |
| --- | --- | --- |
| **降反射次数** ⭐ | Study Area → Reflections **6→2**（或3） | 路径数指数级下降，最大提速 |
| 加大射线间隔 | Ray spacing **0.4°→1.0°** | 射线数降到 ~1/6 |
| 减面 | 重导 `--target_faces 200000` | 面遍历更快（唯一能降毛刺噪声的办法） |
| GPU 加速 | 见下 | 大概率开不了 |

> **GPU 用不上**：日志 `Failed to load OptiX library` = 此版 InSite(2025构建) 的 OptiX **不支持 Blackwell(RTX 50 系, sm_120)**，自动退回 8 线程 CPU。需 Remcom 出支持新架构的 InSite 新版才能 GPU，否则只能 CPU。**先降反射到 2 通常就够快了。** 精算最终图时再把反射调回 4~6 单跑一次。

## 5c. 导出 Cesium for Unreal / UE 模型（.glb + 材质表 + 锚点）· [根]

```cmd
python scripts\export_gltf_ue.py ^
  --material_ply outputs\%SCENE%_pgsr\material_gauss_cons\material_mesh.ply ^
  --geo_transform outputs\%SCENE%_pgsr\geo_transform.json ^
  --out_dir outputs\%SCENE%_pgsr\ue --target_faces 300000
```

**产物**：`ue\{scene_ue.glb, ue_materials.csv, ue_anchor.json}`。glb 面片**按电磁类分材质槽 EM_***，
UE 里 LineTrace 命中即知材质；`ue_anchor.json` 给 **Cesium 锚点经纬高 + TX 建议位**。
**注**：用 `--material_ply`（带色网格顶点色反推材质）可绕开偶发被占用的 `face_materials.csv`；
也可换 `--mesh ...tsdf_fusion_post.ply --materials ...face_materials.csv`。
**完整 UE 实验**（Cesium 地球锚定 + LineTrace 射频覆盖 + 三引擎对比）见
**[docs/UE_Cesium射线实验手册.md](UE_Cesium射线实验手册.md)**。C++ 追踪器在 `ue\RFRayTracer.{h,cpp}`。

## 常见坑速查

| 现象                           | 处理                                                                  |
| ---------------------------- | ------------------------------------------------------------------- |
| COLMAP `unrecognised option` | 去掉该选项                                                               |
| convert.py 找不到 input         | `--data_path` 给**父目录** data（不是 data\%SCENE%）                        |
| 网格空/破碎                       | `--max_depth` 按 `cameras_extent` 调（非米）                              |
| 训练/编译显存不足                    | 加大 `-r`（如 `-r 4`→`-r 8`）                                            |
| 路损 TX 在模型下方                  | `simple_pathloss` 加 `--cameras ...cameras.json`                     |
| HuggingFace 下不动              | 用零下载 `autolabel_color.py`；或 `set HF_ENDPOINT=https://hf-mirror.com` |
| `move` 报 Permission denied   | 关掉 MeshLab/查看器再移                                                    |
| 材质分错                         | 调 `autolabel_color.py` 阈值 / 换 SegFormer / 增补类别                      |
| 无 GPS 无法配准                   | 量已知距离手动算 `--scale`；或用 GCP/RTK                                       |
| **InSite 导入后材质全变一种(Concrete)** | **加载 `scene.city` 不加载 `.dae`**——InSite 的 COLLADA 导入会合并材质；脚本已内置 `write_city` 直写原生格式 |
| **InSite 里模型躺平/翻转**          | 是配准前的 COLMAP 原始坐标；导出加 `--geo_transform`（米制+ENU摆正） |
| **InSite 里地面在 z≈-80**        | 导出加 `--ground_z0`（ENU 原点在无人机飞行高度，故地面偏低） |
| **InSite 仿真慢 / 日志 `Failed to load OptiX`** | Blackwell(RTX50系) 不被此版 InSite 的 OptiX 支持，退回 CPU；降 Reflections 6→2、Ray spacing 0.4→1.0、`--target_faces 200000` 减面 |
| InSite 里模型太小                 | 用 `--geo_transform`（米制）；无配准则手动 `--scale` |
| georeference 读到 GPS 0/N       | 确认原图带 GPS EXIF（手机/无人机/RTK）；脚本已处理 DJI 的 bytes 海拔ref |
| 控制台报 `gbk codec ... ↔` 崩溃 | 已用 ASCII 替代；自改脚本时 print 勿用 ↔ 等非 ASCII 字符 |
| export/move 报文件被占用/锁         | 关掉 VS Code 里打开的大 `face_materials.csv` 标签页 / 等杀软扫完 |

## 全流程一句话

```
影像 → COLMAP → PGSR(3DGS+网格) → 地理配准(GPS→米制+朝向) → 自动材质标注 →
可微材质嵌入高斯(+L_cons) → 迁移到面片 → P.2040 电磁参数 →
射线路损 → 3D 可视化 →→ 导出 Wireless InSite(.city，材质不丢) / Cesium-UE(.glb) → UE LineTrace 射频覆盖 → 三引擎对比
```

参考实现见 `experiments\scene01\`（已跑通的完整样例）。
