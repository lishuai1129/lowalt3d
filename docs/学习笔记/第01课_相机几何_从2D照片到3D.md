## 0. 核心问题

照片是二维的（每个像素只有颜色）。可你的系统要的是三维世界坐标。**凭什么能从 2D 还原 3D？**

> **答案**：一个像素 = 一条从相机射出的光线。光线的**方向**由相机参数决定，光线上**走多远**由深度决定。
> **方向 × 深度 = 三维点。** `unproject_depth` 做的就是这件事。

---

## 1. 三个坐标系（先建立心智模型）

任何 3D 视觉的一切，都是在这三个坐标系之间转换：

```
世界坐标系 (world)          ← 地图最终所在，米制
    ▲   │
    │   │  c2w  (相机位姿: 旋转 R + 平移 t)
    │   ▼
相机坐标系 (camera)          ← 以相机为原点，+Z 指向正前方 (OpenCV 约定)
    ▲   │
    │   │  K   (内参: fx, fy, cx, cy)   ← 投影
    │   ▼
像素坐标 (u, v)              ← 一张照片就是这个
```

- **拍照** = 从上往下走（world → camera → pixel），过程中**丢掉了深度**。
- **重建** = 从下往上走（pixel + 深度 → camera → world），**这正是反投影**。

---

## 2. 投影：相机怎么把 3D 拍成像素

**针孔模型**：相机中心是一个点，场景点 (X, Y, Z) 的光线穿过它打到像平面。用**相似三角形**：

```
像平面上的位置 / 焦距 f  =  场景点的 X / 场景点的深度 Z
        x_img / f       =        X / Z
   ⇒    x_img = f · (X / Z)
```

换成**像素**（焦距用像素单位 fx，再加主点偏移 cx，因为像素原点在左上角、而光轴在图像中心）：

$$u = f_x\cdot\frac{X}{Z} + c_x \qquad v = f_y\cdot\frac{Y}{Z} + c_y$$

写成矩阵就是内参 K：

$$K=\begin{bmatrix}f_x&0&c_x\\[2pt]0&f_y&c_y\\[2pt]0&0&1\end{bmatrix}$$

**关键点：**

- **fx, fy**：焦距（像素单位）。越大 → 视场角越窄（越"长焦 / 放大"）。
- **cx, cy**：主点，一般 ≈ 图像中心。
- 投影里**除以了 Z** —— 这就是"近大远小"，也是**深度信息在拍照时被丢掉**的地方。

---

## 3. 反投影：像素 + 深度 → 3D（你要的核心）

拍照丢了深度。但如果我们**另外知道深度 d = Z**（lingbot-map 帮你预测出来），就能把投影公式**反解**：

$$X = \frac{u-c_x}{f_x}\cdot d \qquad Y = \frac{v-c_y}{f_y}\cdot d \qquad Z = d$$

**对应代码里那三行：**

```python
x = (uu - cx) / fx * d
y = (vv - cy) / fy * d
z = d
```

**直观理解**：$\dfrac{u-c_x}{f_x}$ 是这条光线的"横向斜率"（每往前 1 米向右偏多少），乘以深度 d 就得到真实的横向偏移 X。

**数值例子**（用自测里的 K：fx = fy = 150, cx = 80, cy = 60）：

| 像素 (u,v) | 深度 d | 计算 | 三维点 (X,Y,Z) | 含义 |
|---|---|---|---|---|
| (80, 60) 正中心 | 3 m | (80−80)/150×3 | (0, 0, 3) | 正前方 3 米 |
| (110, 60) 右偏 30px | 3 m | (110−80)/150×3 = 0.6 | (0.6, 0, 3) | 前方 3 米、右侧 0.6 米 |

> 一个像素 + 一个深度 → 一个确定的三维点。这就是重建的原子操作。

---

## 4. 相机坐标 → 世界坐标（位姿 + 齐次坐标）

上一步得到的 (X, Y, Z) 是**相机自己坐标系**里的。要拼进统一的世界地图，得知道**相机此刻在世界的哪、朝哪** —— 这就是**位姿 c2w**（camera-to-world）：

$$\text{world} = R\cdot\text{cam} + t$$

R 是 3×3 旋转（相机朝向），t 是相机在世界里的位置。为了把"旋转 + 平移"合并成**一次**矩阵乘法，用**齐次坐标**（点末尾补个 1）：

$$\begin{bmatrix}\text{world}\\1\end{bmatrix}=\underbrace{\begin{bmatrix}R&t\\0&1\end{bmatrix}}_{c2w\ (4\times4)}\begin{bmatrix}\text{cam}\\1\end{bmatrix}$$

**对应代码：**

```python
cam = np.stack([x, y, z, np.ones_like(z)], axis=-1)   # 末尾补 1 → 齐次坐标
world = (c2w @ cam.T).T[:, :3]                          # 一次矩阵乘完成 旋转+平移
```

> **补 1 的作用**：让"平移 t"也能塞进矩阵乘法。不补 1，矩阵乘只能做旋转，平移得单独加；补 1 后一步搞定。这是图形学 / 视觉的通用技巧。

## 5. 回到代码：`unproject_depth` 逐行对照

现在整个函数你应该能通读了：

```python
uu, vv = np.meshgrid(us, vs)        # ① 枚举所有像素坐标 (u,v)
d = depth[vv, uu]                    # ② 取每个像素的深度
valid = (d > 0) & (d < max_depth)    # ③ 扔掉无效深度(0 或过远)
x = (uu - cx) / fx * d               # ④ 反投影：像素+深度 → 相机坐标 X,Y,Z
y = (vv - cy) / fy * d               #    （第 3 节公式）
z = d
cam = [x, y, z, 1]                    # ⑤ 补 1 变齐次
world = c2w @ cam                     # ⑥ 相机坐标 → 世界坐标（第 4 节）
```

**六步 = 三个坐标系走两趟。这就是"扫描环境重建三维"最底层的那台发动机。**

---

## 6. 为什么这对你的项目生死攸关

- **深度 d 必须是米制** → 否则电磁路损（∝ 距离²）全错。这就是为什么要用 ARKit 位姿给 lingbot-map 锚定尺度。
- **c2w 必须是米制、且去漂移** → iPhone 的 VIO 提供它。
- **坐标约定要一致**（+Z 前 / +Y 下，OpenCV 约定）→ 位姿和内参来自不同库时最容易在这里出 bug，会导致整个场景镜像或旋转。

<details>
<summary>点开查看（请先自己答）</summary>

1. **投影除以 Z**：近大远小 —— 同样大小的物体，离得远（Z 大）在像上就小，所以要除以深度。这一步把 3D 压成 2D，深度信息随之"归一化"掉了。**反投影乘以 d**：是投影的逆运算，既然投影时把真实坐标除了 Z（=深度）才得到像素比例，反解时就要把这个比例乘回深度 d，才能恢复真实尺寸的 X、Y。

2. **fx 翻倍 → 视场角变小**（更"长焦 / 放大"）：由 $u = f_x X/Z + c_x$，同一个 3D 点，fx 越大，像素偏移越大，意味着更小的真实角度就占满整幅图 → 视场更窄。**若 fx 用错（偏大）做反投影**：$X=(u-c_x)/f_x\cdot d$ 里除了更大的 fx，重建出的点会**向光轴收缩**（场景被"压扁 / 变窄"）。所以内参必须与拍摄相机一致。

3. **去掉末尾的 1**：`cam` 变成只有 (x,y,z) 的 3 维向量，`c2w[:3,:3] @ cam` 只会施加**旋转 R**，而**平移 t 完全失效** —— 所有点会被摆到"相机在世界原点"的错误位置。补 1 正是为了让 4×4 的 c2w 里的平移列 t 参与运算。

</details>
